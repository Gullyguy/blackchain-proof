# Contributing

BlackChain Proof welcomes focused contributions that strengthen public utility, privacy, accessibility, security, and Solana interoperability.

## Before opening a pull request

1. Open an issue describing the user problem and proposed change.
2. Keep personal information and live wallet secrets out of issues, tests, fixtures, and commits.
3. Add or update tests for protocol changes.
4. Run `npm test`, `npm run lint`, and `npm run build`.
5. Explain privacy, compatibility, and migration effects in the pull request.

## Design principles

- Demonstrated work beats attendance.
- Learners control disclosure.
- No personally identifiable information belongs on-chain.
- Verification remains public and vendor-neutral.
- Closed commercial services cannot capture the grant-funded open core.

## Security

Do not disclose suspected vulnerabilities in a public issue. Until a private reporting address is published, contact the project lead through BlackChain Collective's established business channel.
